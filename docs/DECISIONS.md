# Decisions — G4 Home-Services Intake Desk

Every call made in this build, numbered. **Provisional** means the owner (Shane) did not answer before the build ran unattended (2026-11-21); the PRD's recommendation (or the most reasonable reading of the spec) was taken and is waiting for his review. Nothing here is a client result: this is a portfolio sample build on synthetic intakes and hand-written recorded router responses. D-1 to D-24 were written before any code; later entries were added as the build met them.

| D-4 | 2026-11-21 | **Provisional — text and web forms only, no voice.** A "missed call" enters as the voicemail/missed-call *transcript text* on its own webhook; no telephony, speech-to-text or audio anywhere. | PRD question 1; owner override 3. |

| D-6 | 2026-11-21 | **Recorded router only; $0 live spend.** `RecordedRouter` replays `fixtures/recorded.json`, which is **hand-written** in the router's output shape — not a recording of a live model. `AgentSdkRouter` (Claude Agent SDK `query`, no tools, structured output, budget cap) is implemented behind the same `Router` interface but **never run**: it refuses to construct without `ANTHROPIC_API_KEY`, and the CLI's `--live` needs the key. | D-7 | 2026-11-21 | **Model and SDK confirmed from primary sources.** Anthropic's models overview (platform.claude.com/docs/en/models/overview, read 2026-11-21) lists `claude-opus-5-5` ($4/$20 per MTok), `claude-sonnet-5-5` ($2/$10), `claude-haiku-5-5` (from $0.10/$0.50) and `claude-fable-5-2` ($8/$40); the first three match G0's `evaluation.PRICES_PER_MTOK`. | D-8 | 2026-11-21 | **Attached to G0 at `6f5e605f8b485afa95f1cbef73911057b8b4dec5`** as a git dependency in `pyproject.toml`, exactly as G3·C does. Capabilities are called in-process through one adapter (`src/intake_desk/layer.py`, modelled on G3's). `health` is called first; a degraded layer or a missing G4 seed stops the run before any routing. g0-shared-layer was read-only for this build. | Owner override 5. |
| D-9 | 2026-11-21 | **Three G4 seeds go in through G0's own documented seed loader**, because the v1 contracts have no register tool (the same exception G2 and G3 make): synthetic contacts `contacts/g4_contacts.json` (ids `g4-c*`, all `@example.com`, per-channel consent flags; G0's loader itself refuses non-example.com), brand policy version **`g4-followup-1`** (`brand/brand_policy_g4_followup_1.json`, rules `g4.*`), rubric **`g4_route_v1`** (`rubrics/g4_route_v1.json`). The adapter refuses any seed not namespaced `g4`, so G0's own rows can never be overwritten from here. G0's contacts table has no phone column, so the caller-ID → contact lookup reads the `phone` key of the same seed file (G0's loader ignores it). | Owner override 5: "use G0's documented seed loader the way G2/G3 do and log it". |
| D-10 | 2026-11-21 | **Channel mapping to G0.** Customer text → consent channel `sms`, brand channel `other`; customer email → consent `email`, brand `email`. Web forms carry a `reply_channel` (sms or email); missed calls reply by sms. | G0's consent enum is email\|linkedin\|sms\|phone; brand's is linkedin\|email\|digest\|post_angle\|other. |
| D-11 | 2026-11-21 | **A deterministic emergency guard runs in code, independent of the router** (`safety.emergency_signals`): strong hazard signals (gas smell, carbon monoxide, burning smell/smoke, sparks, water pouring/burst pipe/flooding, no heat, heat out, furnace off/won't start) or an outage signal plus a vulnerability/extreme-temperature signal (e.g. AC quit + on oxygen / 101°). Any hit forces `escalate`. The report shows missed emergencies **router-only** and **final**, so the guard cannot hide a router miss. | "Zero missed labeled emergencies is the bar" must not depend on a model being right. These are G4's own safety rules, not a G0 capability, so they live in G4 code (never in the prompt). Options: router only (a model miss = missed emergency), guard only (no judgement for the rest), both — chosen. |
| D-12 | 2026-11-21 | **Final-route order, fail closed:** (1) router output invalid → escalate, confidence 0; (2) emergency guard hit → escalate; (3) confidence < threshold → escalate; (4) otherwise the router's route. The decision keeps the router's raw `{route, confidence, reasons}` and appends why it was overridden. | PRD: below the threshold → escalation queue regardless of route; AC2/AC3. |
| D-13 | 2026-11-21 | **Labeling rules for the synthetic set** (PRD route table, made concrete): *book* = clear HVAC service request, normal urgency, enough detail, received in business hours; *follow_up* = missing details, vague, price shopping, after hours and not urgent (even when the request is clear — the PRD puts after-hours non-urgent in follow-up), or wrong trade and not urgent (polite out-of-scope template); *escalate* = emergency, angry customer or dispute, wrong-trade emergency. An on-site estimate request for a still-working system is *book* (a visit), not price shopping. | PRD route table. When a row could fit two routes the PRD's wording decided and the row carries a `tags` note. |
| D-14 | 2026-11-21 | **Business hours** in `config/business.json`: Mon–Fri 08:00–17:00, Sat 09:00–13:00, Sunday closed, `America/Chicago`; `on_call: true`. Evaluated against the intake's `received_at`. The on-call flag only picks the alert target (`on_call_tech` vs `owner`); every escalation still goes to the queue. | PRD inputs list "business hours and an on-call flag". |
| D-15 | 2026-11-21 | **Duplicates:** an intake from the same contact within 24 h of an earlier intake is linked to it (`duplicate_of`). Book/follow-up duplicates create **no second booking and no second outbound** (logged `suppressed_duplicate`); an escalate duplicate is always added to the queue again (a repeat emergency call is new information). The label of a duplicate is the route the router should choose for it. Unknown callers (no contact) are never deduplicated. | PRD lists duplicates as an edge case without saying what to do; never double-book, never swallow an emergency. |
| D-16 | 2026-11-21 | **Consent before every customer outbound** (`audience.consent`, fails closed). Not allowed (unknown caller, no flag, opted out) → the outbound is recorded with status `blocked_consent` and the reason, nothing else; the route is unchanged and the report counts blocked outbounds. **Owner/on-call alerts are internal** (to the business, not the audience), so they are not consent-checked; they are logged-not-sent like everything else. | PRD: "audience.consent: check before any text or email goes out". |
| D-17 | 2026-11-21 | **Brand check before every customer outbound:** follow-up and booking-confirmation drafts come from fixed templates (`templates.py`) and must pass G0 brand policy **v1 and `g4-followup-1`** on their channel; a failure blocks the outbound (`blocked_brand`) and puts the item in the escalation queue. `g4-followup-1` adds home-service rules G0 v1 lacks: no price figures in a text, no arrival guarantees, SMS ≤ 60 words. | PRD: "brand.policy: tone for follow-up messages"; rules live in G0, not the template code or a prompt. |
| D-18 | 2026-11-21 | **The outbox is the only sink.** Every outbound (sms, email, owner alert, booking confirmation) is a row in the desk store's `outbox` table and a line in `out/<run>/outbox.jsonl`, status `logged_not_sent` (or `blocked_*`). No HTTP/SMTP/SMS/calendar client is imported anywhere in the package (test). The calendar is a synthetic table in the same SQLite file. | CLAUDE.md: all outbound logged, never sent; safety invariants first. |
| D-19 | 2026-11-21 | **Router contract** `schemas/router_v1.json`: `{"route": "book"\|"follow_up"\|"escalate", "confidence": 0–1, "reasons": [1–5 non-empty strings]}`, extra fields refused. A non-JSON string or a schema failure raises `RouterOutputInvalid` and the intake escalates (D-12). | PRD: router returns `{ route, confidence, reasons }`; AC1 needs reasons on every route. |
| D-20 | 2026-11-21 | **Escalation queue** (`queue` table): every escalated intake is `pending` until the owner calls approve or reject (CLI or `POST /queue/{id}/approve|reject`). Approve executes the item's proposed action — the router's route when it was book/follow_up, or the owner's `action` override (book, follow_up, owner_handled) — through the same consent/brand/outbox path; reject closes it with nothing sent. Nothing auto-resolves. | PRD: "Wait node for a human decision" — the code equivalent is a durable pending queue. |
| D-21 | 2026-11-21 | **Synthetic calendar:** slots at 08:00, 10:00, 13:00 and 15:00 on the next three business days after the intake (Mon–Fri), one job per slot; book takes the first free slot. No real calendar exists. | PRD: "create the appointment (synthetic calendar)". |
| D-22 | 2026-11-21 | **G0 evaluation holds the labeled scoring.** Each eval-run intake is scored by G0 `evaluation` against rubric `g4_route_v1` (required: `route_correct`, `emergency_safe`) with the deterministic judge; G0 stores every result in its `evaluations` table. The labeled set itself is version-controlled in `fixtures/intakes.json`. Accuracy in the report is computed from those G0 results. | PRD: "evaluation: stores the labeled set and routing accuracy". v1 has no dataset store; each scored item carries its label. |
| D-23 | 2026-11-21 | **Observability and measurement per intake:** one G0 `observability` row per router call (model, tokens, cost — 0 on the recorded path —, note with route, confidence and final route) and one G0 `measurement` event `intake.routed` (route, confidence, final route, overrides; no personal data). The run total and `over_cap` come back from G0. | PRD: "observability: logs each route, its confidence, and cost". |
| D-24 | 2026-11-21 | **Metric definitions.** Routing accuracy = final route equals the label; router accuracy = raw router route equals the label; escalation rate = final escalations / intakes; missed emergency = a labeled emergency whose final route is not escalate (also reported router-only); per-route confusion = label × final route. Sweep: 0.5, 0.6, 0.7, 0.8, 0.9. | PRD AC5. |
